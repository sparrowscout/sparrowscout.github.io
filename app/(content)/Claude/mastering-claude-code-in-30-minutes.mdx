### Context 파일 계층 구조로 사용하기

![Give Claude more context - CLAUDE.md 계층](/img/mastering-claude-code-in-30-minutes/matering-claude-code-in-30-min-6.png)

CLAUDE.md랑 설정은 계층 구조로 로드됨, 우선순위:

```bash
enterprise (조직 관리자가 전사 배포)  ← 가장 위, 직원이 못 덮어씀
   ↓
user/global (~/.claude/, 내 모든 프로젝트)
   ↓
project (repo에 커밋, 팀 공유)
   ↓
CLAUDE.local.md (커밋 안 함, 나만)
```

> [!tip] enterprise root?
> 회사 관리자가 모든 직원의 Claude Code에 강제 적용하는 설정 위치예요. Boris 예시: "이 test 명령은 전 직원 자동 승인", "이 URL은 누구도 fetch 못 하게 차단" 같은 걸 여기 박아두면 개별 직원이 못 바꿉니다. 보안/정책을 중앙에서 거는 용도라, 혼자 쓰거나 작은 팀이면 거의 안 만지는 영역이에요. (정확한 파일 경로는 OS마다 달라서 [공식 문서](https://docs.claude.com/en/docs/claude-code/overview)에서 "settings hierarchy" 확인하는 게 안전합니다.)

> [!tip] Skills
> 커스텀 슬래시 커맨드는 이제 Skills로 통합됐어요.<br/>
> `.claude/commands/`의 파일도 여전히 동작하지만, `.claude/skills/`가 권장 방식이고 둘 다 `/command-name` 형태로 호출됩니다.<br/>
> 즉 본인이 만든 react-next-review 스킬이 사실상 `/react-next-review` 슬래시 커맨드 역할을 해요. 현재 60개 넘는 내장 커맨드가 있고, Claude Code에서 /를 치면 전체 목록이 뜹니다.
>
> > 근데 Skills 쓰다보니까 '이 대화 저장해줘' 하거나 '이력서에 넣을 문구로 수정해줘' 라고만 해도 관련 스킬 알아서 가져와서 쓰는듯

### key bindings

![Interlude: Keybindings](/img/mastering-claude-code-in-30-minutes/matering-claude-code-in-30-min-11.png)

- `Shift+Tab` : auto-accept 모드 (편집 자동수락, bash는 여전히 승인)
- `#` : 기억시키기 → CLAUDE.md 자동 반영
- `!` : bash 모드 — **실행 결과가 그대로 컨텍스트에 들어가서 다음 턴에 클로드가 봄**
- `@` : 파일/폴더 컨텍스트 추가
- `Esc` : 언제든 안전하게 중단 / 두 번 : 히스토리 점프
- `--resume` / `--continue` : 세션 재개, `Ctrl+R` : 전체 출력 보기

### SDK?

![Claude Code SDK](/img/mastering-claude-code-in-30-minutes/matering-claude-code-in-30-min-12.png)

Claude Code를 헤드리스(터미널 UI 없이)로 돌리는 방법 <br/>
claude -p "프롬프트" 형태로 쓰면 사람이 안 보고 프롬프트 → 결과(JSON 등) 만 뱉어주는 함수처럼 동작합니다. Claude Code를 움직이는 그 "에이전트 엔진"을 라이브러리/CLI로 노출한 것 <br/>
//아 GitHub Actions에서 PR 리뷰하게 만든게 SDK를 쓰는거구나//

```bash
cat huge.log | claude -p "이 로그에서 이상한 거 찾아줘" --output-format json
```

> [!tip] SDK
> Claude SDK (현재명: Claude Agent SDK)
> [Agent SDK 개요](https://platform.claude.com/docs/en/agent-sdk/overview) / [마이그레이션 가이드](https://platform.claude.com/docs/en/agent-sdk/migration-guide) — 이름·패키지 변경(`claude-code-sdk` → `claude-agent-sdk`)과 v0.1.0 breaking change가 정리돼 있어요. 옛 `claude -p` 워크플로에서 옮길 때 이거 보면 됩니다.
